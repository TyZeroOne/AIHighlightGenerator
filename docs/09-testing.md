# 09 — Стратегия тестирования

Правило проекта: **этап дорожной карты не считается закрытым без тестов**
(док 10). Ниже — что именно и как тестируем.

## 9.1 Пирамида

```
        e2e (5%)        полный конвейер на 30-секундном видео, в Docker
     integration (25%)  БД, storage, ffmpeg, Celery eager, реальные модели на tiny
        unit (70%)      домен, скоринг, парсеры, схемы, селектор — без I/O
```

Целевое покрытие: **≥ 85 %** для `core/` и `highlight_detector/`,
**≥ 70 %** в целом. Адаптеры, которые целиком — обёртка над внешним бинарником,
покрываются интеграционными тестами, а не моками.

## 9.2 Инструменты

| Инструмент | Роль |
|---|---|
| `pytest` + `pytest-asyncio` | Раннер |
| `pytest-cov` | Покрытие |
| `pytest-xdist` | Параллельный прогон unit-тестов |
| `testcontainers` | Реальные Postgres и Redis в интеграционных тестах |
| `httpx.AsyncClient` + `ASGITransport` | API без поднятия сервера |
| `hypothesis` | Property-based на тайм-код-арифметике и нормализации |
| `ruff` + `mypy --strict` | Линт и типы (часть CI, блокирующие) |

## 9.3 Маркеры

```python
# pytest.ini
markers =
    unit: без внешних зависимостей, < 100 мс
    integration: нужна БД / Redis / ffmpeg
    e2e: полный конвейер
    gpu: требует CUDA
    llm: делает реальный вызов к Anthropic API
    quality: метрики на golden-датасете
    slow: > 10 с
```

`pytest -m "unit"` — на каждое сохранение.
`pytest -m "not e2e and not llm and not gpu and not quality"` — на каждый PR.
Полный прогон — ночью по расписанию.

## 9.4 Фикстуры и тестовые медиа

Хранить настоящие фильмы в репозитории нельзя. Поэтому:

- `tests/fixtures/generate_media.py` — генерирует синтетические клипы через FFmpeg
  (`testsrc2`, `sine`, `anoisesrc`) с **заранее известными** свойствами:
  склейка на 5.0 с, всплеск громкости на 12.0 с, тишина 8–10 с.
  Детекторы проверяются против этой истины, а не «на глаз».
- `tests/fixtures/samples/` — 3 реальных клипа по 20–30 с (CC0), в Git LFS:
  речь на русском, речь на английском, видео без звука.
- `tests/fixtures/golden/` — JSON с экспертной разметкой для `-m quality`
  (тайм-коды + чек-суммы видео, сами файлы качаются скриптом).

## 9.5 Что тестируем на каждом уровне

### Unit

| Область | Примеры проверок |
|---|---|
| `TimeRange` | Валидация, пересечения, IoU, слияние; property-тест: `merge` ассоциативен |
| Тайм-коды | `"00:15:21.480" ↔ 921.48` в обе стороны, граничные значения, > 99 часов |
| Нормализация | Устойчивость к выбросам, поведение при одинаковых значениях, при N < 8 |
| Формула скора | Отсутствующая группа → веса перераспределены, сумма = 100 |
| Селектор | NMS отбрасывает пересечения > 0.3; MMR не даёт 5 одинаковых категорий; лимит длительности соблюдён |
| Реестр плагинов | Дубликат ключа → ошибка; топосортировка учитывает `requires`; цикл → понятная ошибка |
| Pydantic-схемы | Невалидный JSON от LLM отвергается; `score` вне 0..100 отвергается |
| Архитектура | AST-обход: `core/domain` ничего не импортирует; адаптеры не импортируют друг друга |

### Integration

| Область | Как |
|---|---|
| Репозитории | testcontainers Postgres, реальные миграции, round-trip домен ↔ ORM |
| Storage | Одинаковый набор тестов для `LocalStorage` и `S3Storage` (MinIO в контейнере) |
| FFmpeg-обёртки | Нарезка синтетического видео, проверка длительности через `ffprobe` ± 0.05 с |
| Детектор сцен | На синтетике с известными склейками — найдены все, без ложных |
| Whisper | Модель `tiny` на 20-секундном клипе, проверка WER < 0.4 и наличия word-таймингов |
| Celery | `task_always_eager=True` для проверки графа; отдельный тест с реальным воркером на цепочку из 3 задач |
| API | `httpx.AsyncClient`, все коды ошибок, авторизация, идемпотентность `/analyze` |
| Alembic | `upgrade head → downgrade base → upgrade head` без ошибок |

### E2E

Один тест `test_full_pipeline`: 30-секундное видео с речью → `POST /upload` →
`POST /analyze` → поллинг `/status` до `succeeded` (таймаут 10 мин) →
`GET /clips` содержит ≥ 1 клип → `GET /download` отдаёт валидный mp4,
который открывается `ffprobe` и имеет ожидаемую длительность.
Выполняется в Docker Compose с `WHISPER_MODEL=tiny` и `FakeLLMProvider`.

## 9.6 Тестирование LLM-слоя без денег

- `FakeLLMProvider` — детерминированные вердикты, участвует во всех тестах кроме `-m llm`.
- Записанные реальные ответы (`tests/fixtures/llm/*.json`) прогоняются через Pydantic —
  ловит изменение формата ответа API.
- `-m llm` — один живой вызов, ночью: проверяет доступность модели, работу
  `output_config.format` и что `usage.cache_read_input_tokens > 0` на втором запросе.
- Отдельный тест на обработку `stop_reason == "refusal"`: подменённый ответ,
  конвейер должен продолжиться и пометить джоб `partial`.

## 9.7 Тестирование деградации

Явные тесты на то, что система не разваливается:

| Сценарий | Ожидание |
|---|---|
| Анализатор `vision.faces` бросает исключение | Джоб `partial`, клипы есть, признак отсутствует |
| Видео без аудиодорожки | Аудио- и речевые группы пропущены, скоринг по видеопризнакам |
| LLM недоступна | `β=γ=0`, отбор по эвристике, статус `partial` |
| FFmpeg упал на одном клипе | Остальные клипы отрендерены, у этого `status=failed` |
| Воркер убит посреди этапа | `acks_late` вернул задачу, повтор корректен, дублей нет |
| Повторный `POST /analyze` с теми же параметрами | Возвращён существующий джоб, нового не создано |

## 9.8 Метрики качества (`-m quality`)

```bash
pytest -m quality --baseline=tests/fixtures/golden/baseline.json
```

Прогоняет конвейер по golden-датасету, считает `Precision@5/10`, `Recall@10`,
`mAP`, средний IoU. Падает, если `Precision@10` ниже baseline более чем на 5 п.п.
Baseline обновляется осознанно, отдельным коммитом с обоснованием в сообщении.

## 9.9 Производительность

`pytest-benchmark` на горячих участках: нормализация 10 000 сцен, NMS на 5000
кандидатов, парсинг транскрипта. Регрессия > 30 % — падение теста.
Плюс замер `pipeline_stage_duration_seconds` в e2e и сравнение с бюджетом из док 01, §1.7.

## 9.10 CI (GitHub Actions)

| Job | Триггер | Содержание |
|---|---|---|
| `lint` | каждый push | `ruff check`, `ruff format --check`, `mypy --strict src/core src/highlight_detector` |
| `unit` | каждый push | `pytest -m unit -n auto --cov` |
| `integration` | PR | services: postgres, redis; `apt install ffmpeg`; `pytest -m integration` |
| `e2e` | PR в `main` | `docker compose up` + `pytest -m e2e` |
| `quality` | nightly | `pytest -m quality` |
| `llm-smoke` | nightly | `pytest -m llm` (секрет `ANTHROPIC_API_KEY`) |
| `security` | PR | `pip-audit`, `trivy` по образам |

Merge в `main` блокируется, если упали `lint`, `unit`, `integration` или e2e.
