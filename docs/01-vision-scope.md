# 01 — Обзор и границы проекта

## 1.1 Проблема

Длинный контент (фильм 2 часа, подкаст 3 часа, стрим 6 часов) содержит 5–20 моментов,
ради которых его смотрят. Ручной поиск этих моментов — часы работы монтажёра на каждый час
исходника. Задача — свести это к «загрузил файл → получил готовые клипы».

## 1.2 Цель

Production-ready сервис, который:

- принимает видео произвольной длины и жанра;
- находит моменты, интересные **человеку**, а не только «громкие»;
- отдаёт готовый к публикации артефакт: клип + вертикальная версия + субтитры + метаданные.

## 1.3 В границах (Этапы 1–10)

| Возможность | Комментарий |
|---|---|
| Локальные файлы `mp4`, `mkv`, `mov` | Загрузка через API или указание пути на смонтированном томе |
| Фильмы, сериалы, интервью, подкасты, лекции | Разные профили скоринга (см. док 05) |
| Русский и английский язык речи | Whisper multilingual, автоопределение |
| Разбиение на сцены | PySceneDetect (content + adaptive) с фоллбеком на FFmpeg `scdet` |
| Транскрипция с word-level таймингами | faster-whisper + VAD |
| Аудиопризнаки | громкость (LUFS/RMS), паузы, темп речи, эмоции, смех, крик |
| Видеопризнаки | смены планов, движение камеры, оптический поток, лица, число людей |
| LLM-оценка | Claude, строгий JSON, батчи сцен |
| Нарезка | FFmpeg, точная резка по ключевым кадрам |
| Вертикаль 1080×1920 | Smart-reframe по лицам/сэлиенси + фоллбек blur-pad |
| Субтитры | SRT + ASS (караоке-стиль), опциональный burn-in |
| Метаданные | Заголовок, описание, хештеги — от LLM |
| REST API | `/upload`, `/analyze`, `/status/{id}`, `/clips/{id}`, `/download/{id}` |

## 1.4 Вне границ первого релиза (но архитектура готова)

| Возможность | Как будет добавлено |
|---|---|
| YouTube / Twitch / Kick | Новая реализация `SourceProvider` — ядро не меняется (док 02, §2.6) |
| Live-обработка стрима в реальном времени | Конвейер уже работает над `MediaWindow`, а не над «файлом целиком» |
| Веб-интерфейс | API-first, фронт подключается сверху |
| Диаризация (кто говорит) | Отдельный плагин-анализатор `speech.diarization` |
| Мультитенантность и биллинг | `User` в модели данных уже есть, квоты — отдельная таблица |
| Автопубликация в соцсети | Порт `Publisher` в `export/` |

## 1.5 Явные не-цели

- Не пытаемся быть видеоредактором общего назначения.
- Не делаем покадровое распознавание объектов/сюжета (дорого, LLM по транскрипту даёт больше).
- Не гарантируем «художественный вкус» — система ранжирует, финальное слово за человеком.

## 1.6 Сценарии использования

**A. Монтажёр подкаста.** Заливает 2-часовой выпуск, получает 10 клипов по 30–60 с
с субтитрами и хештегами для Shorts/Reels/TikTok.

**B. Контент-менеджер сериала.** Заливает серию, получает моменты категории `action`,
`plot_twist`, `romantic` с тайм-кодами для трейлера.

**C. Аналитик.** Забирает через API не клипы, а сцены с их скорами и признаками —
использует как разметку для собственного пайплайна.

## 1.7 Критерии успеха

| Метрика | Целевое значение |
|---|---|
| Скорость обработки (CPU, 8 ядер) | ≤ 0.5× длительности видео |
| Скорость обработки (GPU, RTX 3060+) | ≤ 0.15× длительности видео |
| Precision@10 по экспертной разметке | ≥ 0.6 (6 из 10 предложенных моментов эксперт считает удачными) |
| Recall по «эталонным» моментам | ≥ 0.7 |
| Стоимость LLM на 1 час видео | ≤ $0.30 при использовании Batch API и кеширования |
| Падение всего джоба из-за одного этапа | 0 — этапы изолированы, частичный результат сохраняется |

## 1.8 Нефункциональные требования

- **Идемпотентность.** Повторный запуск этапа на тех же входных данных не создаёт дублей.
- **Возобновляемость.** Джоб можно перезапустить с любого этапа, не пересчитывая предыдущие.
- **Наблюдаемость.** Структурные JSON-логи, `trace_id` на весь джоб, метрики Prometheus.
- **Ограничение ресурсов.** Лимит на размер файла, длительность, число параллельных джобов на пользователя.
- **Безопасность.** Валидация контейнера через `ffprobe` до обработки; никаких shell-строк —
  FFmpeg вызывается списком аргументов; загруженные файлы вне веб-рута.
